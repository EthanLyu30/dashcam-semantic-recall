# 重新调整后的任务分配

这版分工的原则是：吕霄阳承担完整客户端与原型搬运，倪羽辰聚焦真实后端、视频处理和 AI 检索。这样两人的工作量更均衡，也更容易在答辩中体现各自贡献。

## 吕霄阳负责

客户端、展示层、原型搬运和联调体验。

- 完整接入 `DVR-Semantic` 原型源文件。
- 维护 `docs/prototype-source/` 中的 11 个页面。
- 提供原型运行入口：`apps/desktop_client/run_prototype.py`。
- 提供 Qt WebEngine 原型壳：`apps/desktop_client/prototype_shell.py`。
- 维护客户端 mock 数据和 mock API client。
- 维护 Qt 客户端语义检索页脚手架。
- 负责 `语义检索中心`、`视频库管理`、`系统状态概览`、`证据与日志归档` 的客户端展示和交互。
- 负责把上传、检索、回放、导出按钮接入后端 API。
- 负责演示流程、答辩页面和客户端联调。

## 倪羽辰负责

后端、AI、视频处理和数据落库。

- FastAPI 后端框架和统一错误响应。
- 视频上传、ffprobe 元数据、ffmpeg 转码、切片、抽帧、缩略图。
- 多模态模型 API 接入和结构化输出解析。
- 语义事件生成、向量/关键词检索、结果排序。
- PostgreSQL 核心表和查询/导出/日志记录。
- 播放流、时间轴、事件详情、证据导出接口。
- 人工复核接口。
- 后端测试和技术实现说明。

## 第一阶段共同验收主链路

1. 上传或选择一个样例视频。
2. 后端完成预处理和语义分析。
3. 客户端输入自然语言问题。
4. 后端返回事件列表和时间戳。
5. 客户端点击结果并跳转回放。
6. 客户端发起证据导出。
7. 后端生成导出记录和文件。

## 为什么这样更均衡

原分工里倪羽辰同时背了视频处理、AI、检索、数据库、日志、导出和大量展示接口，风险太集中。调整后，展示型页面、原型搬运、mock 数据、交互联调由吕霄阳承担；倪羽辰只需要优先打通真实后端主链路。
