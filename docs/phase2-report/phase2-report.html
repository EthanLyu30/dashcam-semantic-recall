04

关键落地 ① — FFmpeg 真媒体流水线

用户上传一个 mp4，系统自动产生切片、关键帧和缩略图，并写入 video_segments / frame_analysis。

处理顺序

  • save_upload — SHA-256 校验 + 文件落 originals/
  • probe_metadata — ffprobe 拿 duration/fps/分辨率
  • slice_video — 30s 一段，写 video_segments
  • extract_frames — 1 帧/3 秒，写 frame_analysis（pending）
  • generate_thumbnail — Pillow 缩到 640px
非 mp4 上传自动 H.264/AAC 转码，保证下游能播。

关键代码片段

def run_preprocess(video_id, segment_sec=30,
                   frame_interval_sec=3) -> dict:
    probe_metadata(video_id)
    slice_video(video_id, segment_sec)
    extract_frames(video_id, frame_interval_sec)
    generate_thumbnail(video_id)
    # process_status: preprocessing -> analyzing
    return {"segments": N, "frames": M, ...}
失败路径走 _mark_failed，写 fail_reason 到 videos.fail_reason 后 raise。
05

关键落地 ② — 模型适配器 + 语义事件聚合

两阶段策略：先逐帧分析、再滑窗合并。模型层走适配器，演示用 mock，真模型只需改环境变量。

三套适配器

  • MockAdapter — 基于文件名 + SHA-256 散列，确定性输出，演示稳定不抖。
  • OpenAICompatibleAdapter — 同时跑 DeepSeek-VL 和 Qwen-VL，因为两家都暴露 OpenAI 兼容 messages 协议。base64 图 + 强约束 JSON 提示词。
  • 网络/解析失败 → 静默 fallback 到 confidence=0、event_type=normal，不抛错。

事件聚合规则

  • 扫描 frame_analysis.status='done' 的帧
  • 相邻 ≤10 秒且 event_type 相同 → 合并为一个 SemanticEvent
  • confidence 取参与帧的均值
  • 均值 < 0.75 → review_status='reviewing'（进复核队列）
  • 最终 Video.process_status 推进到 'indexed'

关键落地 ③ — 向量 + 关键词混合检索

用 sentence-transformers 把事件文本变向量做余弦召回，再叠加关键词分数重排；首次运行无需下载模型也能跑。

计算管线

final = 0.6 * cosine(q_vec, ev_vec)
      + 0.4 * keyword_score(query, event)

# 启用真 embedding 时：
#   paraphrase-multilingual-MiniLM-L12-v2 (384d)
# 未启用时：
#   字符 1/2-gram → hash → 384 维 → L2 归一

关键词词典（行业语义对齐）

  • scratch ← 剐蹭 / 刮蹭 / 碰撞 / 擦碰
  • illegal_parking ← 违停 / 停车 / 占道
  • road_obstacle ← 障碍 / 施工 / 围挡 / 路障
  • abnormal_stop ← 急停 / 急刹 / 鸣笛
  • pedestrian_risk ← 行人 / 横穿 / 鬼探头
每次查询同时落 search_queries + search_results 表，留 query_id 便于日志排障。

关键落地 ④ — FFmpeg 真证据切片 + zip 打包

点击"导出证据包"后系统真的会切一段 mp4、抽一张关键截图、生成 JSON+Markdown 摘要并打包，不再是假路径。

📹 clip.mp4

  • 按 start-5s ~ end+5s 切片
  • 优先 -c copy（关键帧对齐时极快）
  • 失败回退到 libx264/aac 重编码

📸 snapshot.jpg

  • 事件中点 ffmpeg -ss 抓帧
  • Pillow JPEG 保存
  • 作为证据的封面图

📝 report.json + report.md

  • event 全字段 + 源视频元数据
  • 中文 Markdown 给人看
  • JSON 给下游程序消费

落地状态

EventExport.status:  queued → exporting → success
                                       ↘ failed (fail_reason 留底)
zip 路径：  media/exports/{event_id}/package.zip
审计：    每次导出写 audit_logs，包含 operator_id / export_type

诚实清单 — 这周没做完的部分

下周阶段汇报时主动说明，避免老师追问时被动。

技术性未实现

  • 真多模态模型调用：演示走 mock；接 DeepSeek/千问只需填 .env 中的 KEY
  • pgvector / PostgreSQL：用 SQLite + 内存余弦等价替代
  • sentence-transformers 真 embedding：默认未装，hash-ngram 兜底
  • HLS 点播 / 异步任务队列：当前同步 FileResponse，长视频会阻塞
  • PDF 摘要：导出包里目前是 Markdown + JSON

辅助页面未接

  • 告警管理中心：静态展示，未接 audit_logs
  • 全天业务报告 / 模型与安全配置：仍是阶段一的页面雏形
  • 权限管理 UI：后端 users.role 字段就绪，前端编辑界面未做
  • 复核中心：API 已经支持 review_status 改写，但页面未把它接上

已知风险

  • Mock 模型输出有随机性，演示前建议先固定一段视频跑一次
  • 长视频首次 process 偏慢，建议演示用 30–90s 素材
